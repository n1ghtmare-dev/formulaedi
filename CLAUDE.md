# Формула Еды — formulaedi.ru

Доставка еды до комнаты в общежитии МАДИ. Монорепо на npm workspaces, Node 20+.

> ⚠️ **Прод живой и на нём чужой сосед.** Сайт развёрнут на `192.168.33.3`, где
> в том же FastPanel крутится **боевой `yesbeat.ru`** (~20 ТБ медиа) и ещё ~25 сайтов.
> Всё, что мы делаем, происходит строго внутри своего каталога. Подробности —
> в разделе «Сервер», грабли — в [DEPLOY.md](DEPLOY.md).

---

## Состав

| | |
|---|---|
| [apps/web](apps/web/) | витрина: React 18, Vite 6, Tailwind 4, lucide-react |
| [apps/api](apps/api/) | NestJS 11 + Prisma 6, слушает `127.0.0.1:4000`, глобальный префикс `/api` |
| [packages/shared](packages/shared/) | общие типы и расчёты между вебом и API |
| [deploy/](deploy/) | скрипт деплоя, PM2-конфиг, образец Nginx, инструкции |
| [tests/smoke.sh](tests/smoke.sh) | HTTP-проверка живости после выкатки |

База — **MySQL/MariaDB**. Раньше был PostgreSQL, переезд завершён коммитом `6576fc0`.
Если где-то встретится `postgresql://`, `.localpg/` или скрипты `pg:*` в
[package.json](package.json) — это мёртвый хвост, ничего не запускает.

## Что готово, а что нет

Витрина отрисована целиком и работает: каталог по категориям, корзина, выбор
доставки в корпус / самовывоза, механика «формул» (списание до 25%, начисление 7%).
При недоступном API витрина сама падает на демо-меню из `sampleMenu.ts` — удобно
для превью, но легко принять за рабочий бэкенд.

**Купить в ней нельзя.** Нет входа по телефону в вебе, нет оформления заказа, нет
личного кабинета, нет админки, нет оплаты. SMS в режиме `dev` — код пишется в лог.

Весь API на сегодня:

```
GET  /api/health
GET  /api/menu
GET  /api/settings
POST /api/orders/preview     ← только расчёт корзины, заказ НЕ создаётся
POST /api/auth/request-code
POST /api/auth/verify
```

Модели в схеме под заказы, платежи и леджер формул есть — эндпоинтов нет.

## Разработка

```bash
npm run dev          # api + web параллельно (web на :6060)
npm run typecheck    # shared + api + web
npm run build        # shared → api → web
```

Локальная база — MariaDB из [docker-compose.yml](docker-compose.yml) (`docker compose up -d`).
Строка подключения — в `.env`, шаблон в [.env.example](.env.example). `.env` в гите нет.

**Prisma-клиент надо генерировать явно:** `npm run db:generate`. Автоматический
`postinstall` от `@prisma/client` в монорепо со workspaces схему в `apps/api` не находит
и оставляет заглушку без типов (~4 КБ вместо ~700 КБ) — сборка API падает с
`Property 'priceKopecks' does not exist on type '{}'`. Локально это может маскироваться
клиентом, сгенерированным ранее вручную.

## Сервер

| | |
|---|---|
| Хост | `192.168.33.3` (LAN), публичный `79.137.237.2` |
| Панель | FastPanel, `https://cp.yesbeat.ru` |
| ОС | Ubuntu 24.04, MariaDB 10.11 |
| Пользователь | `formulaedi`, дом `/var/www/formulaedi/data`, **sudo нет** |
| Код | `/var/www/formulaedi/data/app` |
| Node / PM2 | через nvm в домашнем каталоге: Node 22, PM2 7 (`pm2_home=~/.pm2`) |
| SSH | изнутри LAN `:22`, снаружи проброшен `:50222` |

Root нам не выдан и не нужен — Node и PM2 стоят в домашнем каталоге, ровно как
у соседних сайтов (`ordersflow`, `docsflow`, `music`).

**Витрину раздаёт сам API**, а не Nginx. Сайт в FastPanel настроен как «Обратный
прокси» на `127.0.0.1:4000`, а в этом режиме Nginx файлы с диска не отдаёт вообще
и поле «Рабочая директория» в панели заблокировано. Поэтому в `AppModule` подключён
`ServeStaticModule`: отдаёт `apps/web/dist`, делает SPA-фолбэк, всё под `/api`
исключено. Плюс схемы — конфигурация лежит в репозитории и едет вместе с деплоем.

**Репозиторий не является document root.** В его корне `.env` с паролем БД и
JWT-секретами. Наружу уходит только собранная витрина.

### База

Пользователь БД создан FastPanel как `formulaedi@localhost` — это в MySQL означает
**только unix-сокет**. Prisma по умолчанию ходит по TCP и получает `Access denied`,
хотя `mysql -h localhost` из консоли работает. Поэтому в `DATABASE_URL` обязателен
`?socket=/run/mysqld/mysqld.sock`. Спецсимволы в пароле — URL-кодировать.

База переведена на `utf8mb4` (FastPanel создаёт в `utf8mb3`, где нет эмодзи).

Схема накатывается через `prisma db push` — без истории миграций. Пока проект не в
бою это удобно, но `db push` не отличает переименование от «удалили и создали»:
на боевых данных это потеря. **До первого реального заказа перейти на
`prisma migrate`** — как именно, написано в [DEPLOY.md](DEPLOY.md).

## Деплой

```
push в main       → tests.yml (typecheck + build + bash -n), прод не трогается
merge main → prod → deploy.yml: бэкап БД → код → сборка → схема → PM2 → smoke
```

Раннеры **облачные** (`ubuntu-latest`), ходят на сервер по SSH через проброшенный
порт `50222`, вход по ключу из секрета `PROD_SSH_KEY`. Self-hosted раннер не нужен.

Ручной запуск: Actions → *Deploy PROD* → по умолчанию **dry-run**, который ничего
не пишет и только показывает, что уехало бы. Реальная выкатка — `apply`.
Отдельно есть *Inspect PROD* — read-only осмотр сервера.

Перед каждой записью снимается дамп MySQL в `~/_deploy_backups/formulaedi/`
(хранятся последние 10). Пустой дамп отменяет деплой.

Секреты: `PROD_SSH_HOST`, `PROD_SSH_PORT`, `PROD_SSH_USER`, `PROD_DEPLOY_PATH`,
`PROD_SSH_KEY`. Адрес и путь в секретах, потому что репозиторий публичный.

**Единственная внешняя зависимость — проброс порта 50222 на роутере.** Если деплой
падает на шаге «Проверить связь» — смотреть в первую очередь туда.

Полное описание, первичная настройка сервера, откат и список граблей —
[DEPLOY.md](DEPLOY.md). Секреты и доступы — [deploy/RUNNER-SETUP.md](deploy/RUNNER-SETUP.md).

## Домен

`formulaedi.ru` зарегистрирован на reg.ru, зона там же (`ns1.reg.ru`, `ns2.reg.ru`),
но **на сервер не направлен** — A-записи смотрят на парковку `95.163.244.138`.
Нужно перевести `@` и `www` на `79.137.237.2`, и только после этого выпускать
SSL Let's Encrypt в панели: проверка идёт снаружи по HTTP и на парковке не пройдёт.

Пока DNS не переехал, проверять сайт нужно по IP с заголовком Host:

```bash
curl -H "Host: formulaedi.ru" http://79.137.237.2/api/health
BASE_URL=http://192.168.33.3 HOST_HDR=formulaedi.ru bash tests/smoke.sh
```

⚠️ **С рабочей машины в LAN нельзя проверять ни DNS, ни публичные порты.** Локальный
резолвер отдаёт мусор (`formulaedi.ru` → `127.199.6.200`), а обращение к публичному
IP не проходит из-за NAT. Оба раза это приводило к ложным выводам. DNS спрашивать
с сервера (`dig @8.8.8.8`), доступность портов снаружи — только с облачного раннера.

## Правила работы с этим проектом

- **Любая запись на проде — через пайплайн.** Ручные правки на сервере переживут
  ровно до следующего `git reset --hard` в деплое.
- **Первый прогон после изменений в деплое — всегда `dry-run`.**
- **Пароли не в чат и не в коммиты.** Локальные креды — в `deploy/creds.local.txt`,
  он в `.gitignore`.
- **`.sh` только с LF.** На Windows `core.autocrlf=true`, скрипты уезжают на Linux;
  с CRLF bash падает на `\r: command not found`. Держится правилом в
  [.gitattributes](.gitattributes) — не трогать.
- **Smoke проверяет `Content-Type`, а не только код ответа.** Если Nginx отдаёт
  `index.html` на любой путь, `/api/health` вернёт `200` с HTML, и проверка «код 200»
  это засчитает, хотя API мёртв.
