# Настройка деплоя: секреты и доступы

Раннеры — **облачные** (`ubuntu-latest`), ставить и обслуживать ничего не надо.
Ниже то, без чего пайплайн не поедет.

## Как облачный раннер попадает на сервер

Сервер стоит в LAN (`192.168.33.3`) и из интернета напрямую недоступен. Но снаружи
проброшен порт **50222**, который приземляется на его `sshd`. Проверено с облачного
раннера — SSH-баннер совпал с тем, что отдаёт сервер изнутри:

```
79.137.237.2:50222  →  SSH-2.0-OpenSSH_9.6p1 Ubuntu-3ubuntu13.14   ✓
79.137.237.2:22     →  закрыт
```

Изнутри LAN этот порт не проверяется — NAT даёт ложный отрицательный результат.
Не пытайтесь: `telnet 79.137.237.2 50222` с рабочей машины ничего не докажет.

**Если деплой вдруг начнёт падать на шаге «Проверить связь» — первым делом смотреть,
жив ли проброс 50222 на роутере.** Это единственная внешняя зависимость пайплайна.

## Ключ доступа

Пара сгенерирована специально для деплоя, паролей нигде не используется:

```
~/.ssh/formulaedi_deploy       приватный — лежит в секрете PROD_SSH_KEY
~/.ssh/formulaedi_deploy.pub   публичный — добавлен на сервере через FastPanel
```

Публичный ключ прописан пользователю `formulaedi` в `~/.ssh/authorized_keys`.

Воркфлоу кладёт приватный ключ во временный файл, работает и удаляет его шагом
`if: always()`. Хост пинится через `ssh-keyscan` в `known_hosts` — защита от подмены
сервера по пути.

## Секреты репозитория

Settings → Secrets and variables → Actions:

| Секрет | Значение |
|---|---|
| `PROD_SSH_HOST` | `79.137.237.2` (публичный IP) |
| `PROD_SSH_PORT` | `50222` |
| `PROD_SSH_USER` | `formulaedi` |
| `PROD_DEPLOY_PATH` | `/var/www/formulaedi/data/app` |
| `PROD_SSH_KEY` | содержимое приватного ключа целиком |

Адрес, порт и путь держим в секретах, потому что репозиторий **публичный** —
внутреннюю топологию наружу не светим.

`PROD_DEPLOY_PATH` — это **репозиторий**, а не document root сайта. Наружу отдаётся
только собранная витрина, и раздаёт её сам API.

## Что это стоит по безопасности

Приватный ключ хранится в секретах GitHub — зашифрован, в логи не попадает
(GitHub маскирует), но копия живёт вне нашей сети. Ключ выдан обычному пользователю
сайта: у него **нет sudo**, и дотянуться он может только до своего домашнего каталога.
Даже полная компрометация ключа не даёт доступа к соседним сайтам, включая боевой
`yesbeat.ru`.

Альтернатива без этого риска — self-hosted раннер прямо на сервере: тогда SSH из
пайплайна уходит совсем. Если решим вернуться к этому варианту, понадобится роль
Admin на репозитории и регистрационный токен.

## Грабли

- **Проброс порта.** Единственная внешняя зависимость. Порт 22 снаружи закрыт,
  внутренний адрес из интернета недоступен — работает только 50222.
- **Соседний прод.** На машине живёт боевой `yesbeat.ru`. Скрипт деплоя работает
  строго внутри `PROD_DEPLOY_PATH`, sudo у пользователя нет.
- **Smoke ходит по IP с заголовком `Host`.** Не по домену: пока DNS не переехал
  с парковки reg.ru, обращение по имени ушло бы не туда.
